NARRATIVE 01 // HOW I GOT STARTED

"I didn't start with a big master plan.
I just asked: How does this actually work?"

Every project I've started began because I was curious about a mechanic or an idea. I didn't want to just look at software from the outside—I wanted to open up the editor, write the code myself, and see what happens.

I'm still learning, experimenting, and improving with every build. I don't pretend to know everything. When something breaks, that's usually where the most interesting lessons begin.

“

The best way to understand how something works is to try building it yourself.

— Personal Dev Notes

NOTEBOOK ENTRY // FIELD NOTES

"The compiler error is my most honest teacher."

When I first started, red terminal errors felt intimidating. Now I realize they're just the computer giving me clues. Most of what I know came directly from fixing things I broke.

Note to self: Don't fear the stack trace.

"Getting confused is just the first step of learning."

Whenever I pick up a new tool like Godot or a new language, it feels overwhelming at first. But pushing through that initial confusion and building a small working project is the fastest way I've found to grow.

Curiosity thrives outside the comfort zone.

"Tutorials help, but building is where it clicks."

Reading documentation and watching videos gives you a map, but the real learning happens when you close the tutorial, open a blank editor, and write the code yourself.

Build regularly, even if it's just small experiments.

CHAPTER 05 航海日誌

THE LOGBOOK

A chronological record of milestones, breakthroughs, and learning phases.

PHASE 01 THE FIRST STEPS

Writing My First Lines of Code

Wrote my first simple scripts. Finding out that websites and programs aren't black boxes—they're built with human logic that anyone can learn if they're willing to try.

KEY TAKEAWAY: Anything built by someone else can be understood with patience.
PHASE 02 BUILDING FOUNDATIONS

Learning Core Logic & Interactivity

Moved from basic syntax to understanding functions, variables, and event listeners. Built small interactive tools and learned how to structure code cleanly.

KEY TAKEAWAY: Writing clean, organized code makes debugging much easier later.
PHASE 03 GAME DEV EXPLORATION

Diving into Godot & Night Harvest

Picked up Godot and GDScript to build Night Harvest. Figured out 2D tilemaps, delta time, collision layers, and simple state machines for crop lifecycles.

KEY TAKEAWAY: State machines make real-time games much more predictable and manageable.
PHASE 04 // PRESENT CURRENT CHAPTER

Constantly Learning & Building

Sharpening my frontend craft, exploring web interfaces, diving deeper into game mechanics, and working on upcoming projects. Excited for what's ahead.

STATUS: Hungry to learn, experiment, and collaborate.
